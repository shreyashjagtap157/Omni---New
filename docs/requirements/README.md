# Omni requirements suite

Classification: Informative

This folder is the stable project-intent and provenance hub. The requirements are traceability aids, not language semantics.

1. [User requirements baseline](USER_REQUIREMENTS_BASELINE.md) — complete recovered product/language/compiler/runtime/tooling/assurance intent.
2. [Source reconciliation](SOURCE_RECONCILIATION.md) — source provenance, authority and unresolved historical gaps.
3. [Owner working preferences and repository expectations](../project/OWNER_WORKING_PREFERENCES_AND_REPOSITORY_EXPECTATIONS.md) — execution style and required end state.
4. [Installer and release qualification](../project/INSTALLER_AND_RELEASE_QUALIFICATION.md) — Windows toolchain install, lifecycle, signing and distribution criteria.
5. [Archive index](../project/ARCHIVE_INDEX.md) — preserved source material and status boundaries.

The `OMNI-UR-*` identifiers in the baseline are project traceability keys only. Normative Edition 1 requirements and semantics remain governed by the active, hash-bound `spec/` hierarchy and accepted project governance.
